How the optimizations “work” (at a glance)

Canonical first 3‑value: score the first step that reaches exactly three value‑classes (ignore tails).

Pair‑core + latent rescue: find the stable pair across 7/6/(5). If the third class {05} existed at step‑0 but got deleted later, spawn a candidate {pair + latent} as well as {pair + observed third}.

Pair‑preserve alt‑path (bounded): a tiny re‑run that pins the latent class and allows one mirror follow‑through to drop the competing third. This prevents “we deleted the winner.”

Repeats & resonance: credit the same triple if it repeats across columns, methods, sets, and charts (Midday/Evening/Combined).

4‑value near‑hits: if a step has 4 classes but one is weak, score the nearest triple (the 4→3 you asked for).

Dominance inside long strings: detect that a triple is already “filling” a long string (your 66333111 example) even before full reduction.

Vertical stability: tiny tie‑break from R2/R4/R6/R8 agreement for that box (CSV read as text so Excel sci‑notation can’t corrupt digits).

Mirror‑double alert: early XXY/XYY precursors nudge families with doubles.

(Later) Key‑Digit / Key‑V‑Trac overlay: when a single digit or family is especially sticky, allow a few capped expansions beyond the main family. This is your “special significance” idea—parked until core is stable.
