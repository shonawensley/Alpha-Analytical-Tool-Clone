3) “Health helpers” and regression protection

This is a very good instinct, especially as a non-coder.

Stable already has some strong health guards now:

Schema guard (validate_stable_schema.py) enforces:

Scores/Families/Compound column sets.

Metrics keys (including winner_hits).

Spotlight columns.

Combined coverage for winners.

Unit tests (tests/test_stable_metrics, tests/test_stable_compound, tests/test_stable_training_bundle) cover:

metrics behaviour when winners exist,

compound scoring (caps, funnel, VT-only, etc.).

To push this into “comfort zone” for you, I’d add two more lightweight health mechanisms:

3.1 Golden-fixture regression test

Create a tiny fixture state (fixtures/StableMini) with:

Hard-coded tiny scores/compound CSVs or a tiny workbook snippet.

Known expected metrics: e.g., “winner 123 must have best_compound_rank 1”.

Add a test: tests/test_stable_regression.py that:

runs Stable on that fixture or loads the fixture outputs,

asserts the winner’s best_compound_rank and a few key flags (vt_only_lane, funnel_precol1) have expected values.

Then if a future Codex change breaks something, the test will fail.

3.2 Lightweight “state health” metrics per run

Extend metrics.json (or add a separate health.json) to include:

total_patterns, total_families, avg_top_hot_density (already there),

maybe num_compound_rows, num_vt_only_lane_true, num_funnel_precol1_true.

Over time you’ll know the “normal range” for these. If a state suddenly has total_patterns=0 or avg_top_hot_density=0.0, something is clearly wrong.

These are cheap and don’t change scoring at all; they just give you early warning if a run is broken.

Combined with the schema guard + tests, that’s a solid defence against regressions and silent “bad data”.

Exact digit straight (best)


Exact digit boxed


V-TRAC boxed (correct VT family, eight combos)

winner_hits[w]["vtrac_boxed"] + is_vtrac_boxed flags give us #3.
