Golden rules

Aux draw-path drift (2025-10)

Symptom checklist
- Aux page shows "Working modules unavailable or no draws found" while Dev Health reports canonical module paths.
- V-TRAC analysis throws `draws_1000` / local variable errors despite CSVs living under `data/cleaned/draws/`.

Guardrails (must run)

# modules/_paths.py
from pathlib import Path

def repo_root() -> Path:
    # This file lives in repo_root/modules/_paths.py -> parents[1] is repo_root
    return Path(__file__).resolve().parents[1]

def data_dir() -> Path:
    d = repo_root() / "data"
    d.mkdir(parents=True, exist_ok=True)
    return d

def runs_dir() -> Path:
    r = data_dir() / "runs"
    r.mkdir(parents=True, exist_ok=True)
    return r


Import this everywhere for file paths.

Never call os.chdir.

Never build paths with string concatenation; always use Path.

3) Bootstrap import shim (kills “which module did I import?”)

Use this to make both names (vtrac_reference and modules.vtrac_reference) resolve to the same file (same for analyze_pairs). Drop‑in works on Windows/macOS/Linux.

# modules/bootstrap_imports.py
import importlib, sys
from pathlib import Path

def _alias(module_name: str, alias: str):
    if alias not in sys.modules:
        sys.modules[alias] = sys.modules[module_name]

def ensure_ssot():
    # Always import the canonical modules under 'modules.'
    v = importlib.import_module("modules.vtrac_reference")
    a = importlib.import_module("modules.analyze_pairs")

    # Back-compat aliases (OLD code may use bare names)
    _alias("modules.vtrac_reference", "vtrac_reference")
    _alias("modules.analyze_pairs",   "analyze_pairs")

    # Guardrail: if someone imported bare first, ensure it's the same file
    try:
        vb = importlib.import_module("vtrac_reference")
        ab = importlib.import_module("analyze_pairs")
        assert Path(v.__file__).resolve() == Path(vb.__file__).resolve(), \
            f"Two different VTRAC modules:\n{v.__file__}\n{vb.__file__}"
        assert Path(a.__file__).resolve() == Path(ab.__file__).resolve(), \
            f"Two different analyze_pairs modules:\n{a.__file__}\n{ab.__file__}"
    except Exception:
        # If bare names aren't used, it's fine.
        pass

    return {"vtrac": v.__file__, "analyze_pairs": a.__file__}

4) Run controller & cache (run once, read everywhere)
# core/run_controller.py
import hashlib, json
from pathlib import Path
from datetime import datetime
from modules._paths import runs_dir

def short_md5(b: bytes) -> str: return hashlib.md5(b).hexdigest()[:8]

def start_run(excel_bytes: bytes, date_label: str) -> str:
    run_id = f"{date_label}_{short_md5(excel_bytes)}"
    (runs_dir() / run_id).mkdir(parents=True, exist_ok=True)
    with (runs_dir()/run_id/"run.json").open("w", encoding="utf-8") as f:
        json.dump({"run_id": run_id, "date_label": date_label,
                   "created": datetime.utcnow().isoformat()+"Z"}, f, indent=2)
    return run_id

5) Run ledger & winners gating
# storage/run_ledger.py
import json
from pathlib import Path
from modules._paths import runs_dir

def _path(run_id: str) -> Path: return runs_dir()/run_id/"checklist.json"

def load(run_id: str) -> dict:
    p = _path(run_id)
    return json.loads(p.read_text()) if p.exists() else \
           {"core_done": False, "aux_done": False, "combined_done": False, "winners_posted": False}

def mark(run_id: str, key: str, val: bool=True):
    ck = load(run_id); ck[key] = val
    _path(run_id).write_text(json.dumps(ck, indent=2))

def block_winners(run_id: str) -> bool:
    ck = load(run_id)
    return not (ck["core_done"] and ck["aux_done"] and ck["combined_done"])

9) Common failures & the 10‑second fixes

IndentationError after an if (like your screenshot).
A merge left an empty if block before def .... Add pass or remove the stray if. Also enable an .editorconfig with indent_style = space and run a quick linter pass.

Mixed imports (bare vs. modules.*).
Symptom: Aux numbers don’t match legacy or tables are empty. Fix: add the bootstrap shim call at the top, replace bare imports with from modules..., re‑run smoke tests.

Wrong cwd / wrong interpreter.
Symptom: draws not found, paths resolve to ~ or OneDrive. Fix: always launch via a preflight that prints cwd, python, and confirms the CSV inventory. Health expander confirms at runtime.

Re‑processing on every page click.
Symptom: streamlit logs show reruns and long waits. Fix: make pages read from runs/<run_id>/** and only recompute on button click.

Artifacts inside source tree.
Symptom: git diffs show JSON spew in /app or /modules. Fix: write only under data/runs.

11) Ready‑to‑paste Combined “Aggregated Doubles S” (brief)
# modules/combined_doubles.py
from collections import defaultdict
from typing import Dict, List
def draws_since_last_double(draws: List[str]) -> int:
    for i, d in enumerate(draws):
        if len(set(d)) < 3:  # any double or triple
            return i
    return len(draws)

def aggregated_doubles(states_draws: Dict[str, List[str]], window=100):
    per_state = []
    per_pair  = defaultdict(lambda: {})
    for st, dr in states_draws.items():
        ds = draws_since_last_double(dr[:window])
        # last double base per state (optional: track which '11','22',...)
        per_state.append({"State": st, "DrawsSince": ds})
        # per double base across states (illustrative: treat '11','22',...'99')
        for x in range(10):
            pair = f"{x}{x}"
            # naive: gap since any draw containing that pair in any position
            g = next((i for i,d in enumerate(dr[:window]) if pair in (d[0]+d[1], d[1]+d[2], d[0]+d[2])), window)
            per_pair[pair][st] = g
    # summarize max & states
    agg = []
    for pair, m in per_pair.items():
        mx = max(m.values()) if m else 0
        top = [s for s,v in m.items() if v == mx]
        agg.append({"Double": pair, "MaxGap": mx, "States": ", ".join(top)})
    # sort for display
    per_state.sort(key=lambda r: r["DrawsSince"], reverse=True)
    agg.sort(key=lambda r: r["MaxGap"], reverse=True)
    return per_state, agg

Below is a concrete, project‑wide playbook you can use for any module you add (not just Aux), plus a safe “archive & rename” procedure for cleaning up the legacy scripts without reigniting path chaos.

A. “Add a new module” — the 10‑step playbook (works for any tool)

0) Snapshot & freeze (1 minute)

Commit what works. Tag it (e.g., aux-v1.0-freeze).

From now on, all new work happens on a feature branch (e.g., feature/blackapple, feature/sums).

1) One and only one package root

Treat <repo>/modules/ as the single source of truth (SSOT) for reusable code: modules/vtrac_reference.py, modules/analyze_pairs.py, etc.

Rule: no top‑level duplicates like vtrac_reference.py outside modules/.

Launcher sets PYTHONPATH=%CD% (Windows) before starting Streamlit so modules.* resolves cleanly.

2) Import policy (make drift impossible)

Always import shared code as from modules.X import Y.

Never import bare names (from vtrac_reference import …) or mutate sys.path inside modules.

Add a tiny guard at app startup to fail fast if a duplicate sneaks in:

import importlib
v = importlib.import_module("modules.vtrac_reference")
try:
    alias = importlib.import_module("vtrac_reference")
    assert getattr(alias, "__file__", None) == getattr(v, "__file__", None), \
           f"Two different VTRACs detected:\n{v.__file__}\n{alias.__file__}"
except Exception:
    pass


3) Adapter first, then UI

Before wiring a new page, write a tiny adapter that converts your app’s raw state (draws, dates) into the exact shape the module expects. That’s how you kept Aux stable; reuse that pattern for every module.

4) Health block on every new page (DEV‑only)

In each page, add the System Health expander you already use: print cwd, Python path, and __file__ for the module you just added. This instantly confirms you’re importing from <repo>\modules\..., not a stray copy.

5) “Run once per dataset” contract

New modules must read inputs from the active run cache (e.g., runs/<run_id>/inputs.json) and write outputs back under runs/<run_id>/<module>/….

UI tabs should read from that cache; only a single Process button (per run) performs the heavy compute. This eliminates “press again on every page.”

6) Checklists gate winners

Add the module’s completion flag to the Run Checklist (e.g., blackapple_done: true).

Winners Logger is enabled only when required flags are green (core, Aux, new module).

This guarantees your “day” has a full, consistent set of outputs before posting winners.

7) Naming & constants

Put all thresholds/knobs for the module at the top of its file (constants), not sprinkled through the code, and don’t expose sidebar sliders until you truly need them. (This keeps runs deterministic.)

8) Minimal acceptance test (copy/paste template)

For each module, add a 30‑line script under scripts/verify_<module>.py that:

prints the module path (__file__),

loads a small test draw list,

asserts 2–3 invariants (e.g., non‑empty candidates, expected row counts).

Run it once pre‑commit. If this passes, the UI almost always “just works.”

9) Persist & ignore

All module outputs live under runs/…; add /runs/ to .gitignore.

Don’t write outputs into source folders—keeps the repo clean and diffs sane.

10) Document the surface

Each module should expose one function (e.g., analyze_blackapple(draws) -> dict) and one label helper, plus a 5‑line docstring telling future AIs what the function returns.

For Blackapple, you already have the contract: score, triggers, top candidates, status label.

B. “Archive & rename” without breaking anything (what you asked to do now)

You absolutely can—and should—lock the integrated app and remove the pasted legacy clutter. Do it in three safe passes:

Pass 1 — Quarantine out of the import path

Create /_archive/ at the repo root.

Move all old/duplicate Aux scripts and experimental folders there (use git mv so history follows).

Ensure /_archive/ has no __init__.py and is not added to PYTHONPATH.

Grep for any remaining references:

git grep -n "from vtrac_reference import"
git grep -n "from analyze_pairs import"
git grep -n "sys.path.append"


Fix callers to from modules.* import …; delete any sys.path edits.

Pass 2 — Canonicalize names

Inside modules/, rename files to match how they’re imported today (use git mv):

vtrac_reference.py, analyze_pairs.py, etc.

If you must keep compatibility for older scripts, leave a tiny shim:

# vtrac_reference.py (compat shim at repo root, optional)
from modules.vtrac_reference import *


(Better: delete shims once the grep shows no direct imports.)

Pass 3 — Prove it works

Start the app; open the Health expanders on each page and read the path line.

You should only see <repo>\modules\….

Run the minimal verifiers (Step 8).

When green, delete any leftover shims at the root.

Why this avoids path bugs: Python only finds one copy (under modules/). Nothing in code alters sys.path. Anything “old” sits outside the import path in /_archive/. The Health block tells you instantly if a stray import reappears.

C. Specific to Aux now (VTrac + Blackapple + small adds)

VTrac is unified if and only if every import is from modules.vtrac_reference import … and the Health block shows that file path. If you still have any bare from vtrac_reference import …, fix those now; that single change removes 90% of “mystery mismatches.”

Blackapple stays a single module file (e.g., modules/blackapple.py) with a short, documented interface. Your Control Center table should show BA‑Score, Status, Triggers, #Candidates, Examples; when you need the full list, open an expander. That keeps the UI crisp while still exposing all 12 recommendations if you choose to show them.

Light Aux adds (that won’t destabilize paths): sums/short‑sums tags beside combos, an index watchlist, and the “Aggregated Doubles S” card on Combined. Each of these can be implemented as pure readers over the same run cache—no extra loaders, no new import entry points.

D. “Do we delete or rename?” — my recommendation

Don’t hard‑delete immediately. Move all non‑used scripts to /_archive/ and commit.

Leave them there for one or two weeks of daily runs. If no one misses anything, you can prune the archive later.

This gives you the clarity of a clean tree and an easy rollback path if you discover a hidden dependency.

6. Streamlining outputs after we trust the brain

You also brought up a key point:

“We probably won’t want 5–6 outputs per tool at the very end; the brain will know a lot already, and some outputs are just ‘projectors’.”

Totally agree.

 

The sequence should look like this:

Now:

Keep outputs slightly redundant but very informative: per_item, top, overlay, a couple of reports.

Use them to really understand the DR brain and to tune it.

Master validation phase (aggregator build):

Decide what features/columns are truly valuable for hitting winners.

Decide which projectors you still need for human understanding.

Final optimization pass:

Trim the outputs to the smallest set that still gives:

Enough evidence for aggregator

Enough visibility for you (to audit, troubleshoot, celebrate wins)

Remove redundant or low-value artifacts (e.g., multiple HTMLs that show the same thing differently).

So yes: you’re absolutely on the right track thinking “once we’re happy with how the brain thinks, we can simplify the projector layer.”

7. How this all supports profitability / “when to play” logic

Your profitability vision also fits nicely:

Tools as environment scanners, not just “pick 10 numbers” machines.

With aggregator in place, you can eventually:

Detect “high‑quality environments”:

multiple tools strongly agree on a handful of candidates,

evidence is deep (VT‑straight hits, clustering, Stable persistence, etc.).

Detect “chaotic/noisy environments”:

tools disagree, evidence is thin, winners often live in fringe boxes.

Then your strategy can be:

Play hard when the environment looks favorable (strong, consistent signals).

Sit out or downsize when the environment sucks.

That is exactly the type of “super brain” decision logic you’re describing: it’s not just picking numbers, it’s deciding when it’s even worth engaging.

8. How we reuse what we’ve learned here for Master Validation

Per‑day, per‑state evidence bundles.

Distinguishing live outputs vs frozen snapshots.

Use the same pattern:

Live folders for dev,

sharepacks/bundles for any run we care to analyze seriously or train on.

That will make the master validation and eventual aggregator build much smoother than the fights we had while tuning individual tools in isolation.
