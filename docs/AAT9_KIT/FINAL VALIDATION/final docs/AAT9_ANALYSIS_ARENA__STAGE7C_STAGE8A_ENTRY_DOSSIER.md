## 5. Stage 8A Shadow Candidate-Object Schema

Stage 8A must begin with one object per
`state_key + draw_slot + canonical candidate root` for a single prediction
cycle. `straight_values` and VTRAC linkage live inside that object. Final
boxed/straight production happens later in Stage 8B, not here.

Core rule:

- the object must explain why a value is present
- what lane produced or preserved it
- what it is allowed to influence
- what blockers and risks are still attached

### Required Field Groups

| Group | Required Fields | Purpose | Explicitly Not Allowed |
| --- | --- | --- | --- |
| identity | `candidate_object_id`, `state_key`, `draw_slot`, `canonical`, `straight_values`, `vtrac_index`, `vtrac_straight_lane` | define the candidate root cleanly | mixing multiple roots into one pooled object |
| lane and permission | `primary_lane`, `expression_permission`, `support_role`, `restraint_role`, `decay_role`, `bonus_ball_role` | say what kind of evidence this is and what it may do | silent escalation from context to candidate |
| traceability and dedup | `source_trace_ids`, `source_family_trace`, `lineage_dedup_key` | preserve lineage and stop duplicate credit | score inflation through overlapping sources |
| evidence summaries | `same_day_evidence_summary`, `decay_evidence_summary` | separate same-day evidence from delayed/carryforward evidence | blending decay into same-day proof |
| risk and blocker state | `fresh_confirmation_status`, `denominator_status`, `false_positive_pressure`, `pool_pressure`, `rank_context`, `blocked_reasons` | keep risk and unresolved blockers attached to the object | treating risk as optional commentary |
| downstream allowance | `allowed_next_use` | define what downstream is allowed to do with the object right now | direct production or budget use |

### Controlled Permission Vocabulary

The object should use a controlled permission vocabulary:

- `blocked`
- `candidate_shadow_only`
- `support_research_only`
- `penalty_research_only`
- `companion_only`
- `readback_reference_only`
- `blocked_until_future_confirmation`

This schema is shadow-only. It must not contain:

- live composite scores
- live rank values used for production
- production boxed sets
- production straight sets
- budget weights
- spend caps
- recommended wagers
- decay-adjusted same-day permission

| Question ID | Target | Question | Pass Shape | Failure Shape | Why It Matters |
