Apply the following source rules:

1. Treat explicit user explanations and raw worked tables as primary
   historical training evidence.
2. Treat old assistant summaries as secondary interpretations. Preserve a
   summary only when it agrees with the raw table and the project's VTRAC
   mapping.
3. Treat chart names, physical left/right descriptions, old set counts, and
   proposed scripts as historical context. Lock current coordinates from the
   artifact being reviewed.
4. Use explicit column labels rather than prose such as "leftmost" or
   "rightmost." In this training convention, `7` is the deeper/older box and
   `1` is the latest/more-satisfied box unless the source artifact explicitly
   proves otherwise.
5. Do not convert a curated winner-aware example into a measured hit rate.
6. Preserve candidate burden and identity level. A related digit fragment is
   not an exact, canonical-box, boxed-VTRAC, or ordered-lane hit.
7. Exclude historical wagering progressions and profitability claims from
   extraction doctrine. Cost and candidate width remain valid evaluation
   fields, but financial promotion requires a separate validated process.

## Claim Types

Every material entry must use one of these labels:

- `LOCKED_DOCTRINE`: explicitly taught extraction/convey principle.
- `DETECTION_DEFINITION`: operational way to recognize a taught principle.
- `WORKED_EXAMPLE`: evidence from a named state, date, period, or table.
- `PRE_RESULT_OBSERVATION`: available without the joined result.
- `POST_RESULT_AUTOPSY`: learned only after result reveal.
- `MECHANISM_HYPOTHESIS`: recurring explanation not yet validated.
- `PROPOSED_SYSTEM_CHANGE`: possible future feature, tool, or architecture
  change.
- `VALIDATION_REQUIREMENT`: replay, denominator, burden, control, or holdout
  needed before promotion.
- `OPEN_QUESTION`: unresolved ambiguity requiring instruction or evidence.
- `REJECTED_OR_REVISED`: superseded interpretation with its reason preserved.

## Evidence Discipline

For every example, record:

- state, date, target period, and source variant;
- exact source artifact and table coordinates;
- whether the result was hidden or visible;
- zone and pathway stage;
- identity level: exact literal, canonical box, boxed VTRAC, ordered lane,
  pair/fragment, or broad territory;
- supporting pattern progression;
- competing patterns and candidate burden;
- extraction route and width;
- what was known before reveal;
- what was learned after reveal;
- confidence and unresolved ambiguity.

Never convert a post-result discovery into pre-result credit.

## Foundation Analysis Protocol

Use this sequence for future blind examples unless focused training explicitly
amends it.

### Pass 0 - Coordinate And Clock Lock

Before interpreting a table:

- record state, date, target period, artifact, variant, set/section, and
  column orientation;
- state which draws were available before the target;
- hide the target result;
- prohibit reductions using any draw that was not available at the target
  clock.

### Pass 1 - Raw Pattern Inventory

Without deleting or transforming digits:

1. scan each mini-set vertically across R2/R4/R6/R8;
2. scan each R row horizontally through the box progression;
3. scan mature columns `1` and `2` across sections;
4. scan deeper columns for embedded clusters;
5. compare related sets or recent tables for lingering patterns;
6. compare Midday, Evening, and Combined only after each variant has an
   independent read;
7. record consensus separately from the candidate patterns it supports.

For every pattern, retain:

- raw string and exact coordinates;
- literal identity;
- canonical literal box;
- ordered VTRAC lane where applicable;
- boxed VTRAC identity;
- duplicates and mirror partners;
- whether order is stable, permuted, or absent.

### Pass 2 - Predeclared Reduction Matrix

Historical examples use several useful reduction families:

- latest own-period draw;
- latest Combined or immediately preceding cross-period draw;
- an older but still available same-period draw;
- forward transit order;
- reverse transit order;
- one digit at a time;
- cumulative exact-digit removal;
- mirror-expanded removal;
- deep-column emphasis, commonly `7/6/5`;
- mature-column emphasis, commonly `2/1`.

Do not choose among these routes after seeing which one leaves a desirable
answer. Before execution, declare the route tuple defined by `D019`. Preserve
the unreduced string and every intermediate residual.

### Pass 3 - Residual Re-scan

After each predeclared route:

- distinguish a pattern that already existed from one merely made more
  visible;
- distinguish a newly created residual from an independently repeated
  pattern;
- normalize literal, canonical, ordered-VTRAC, and boxed-VTRAC identities;
- compare the residual with the raw inventory;
- record reduction-route duplication so the same evidence is not counted
  repeatedly.

### Pass 4 - Convergence Receipts

Do not collapse evidence immediately into one unexplained score. Report these
axes separately:

- vertical R-row support;
- horizontal adjacent-box span;
- section/set persistence;
- recent-table persistence;
- cross-variant support;
- consensus adjacency;
- raw versus reduction-only support;
- literal support;
- canonical-box support;
- ordered-VTRAC support;
- boxed-VTRAC support;
- pair/fragment-only support;
- transformation distance;
- independent lineage count;
- competitor count and candidate width.

### Pass 5 - Candidate And Permutation Formation

Candidate formation follows the evidence level:

1. preserve exact embedded literals;
2. preserve exact ordered-VTRAC lanes;
3. preserve canonical literal boxes;
4. preserve boxed-VTRAC territories;
5. use pair or fragment clues only as supporting evidence;
6. derive straight permutations only where progression order supplies
   ordering evidence;
7. if pair-plus-mirror expansion is used, list every generated member and its
   total width rather than crediting only the eventual winner.

### Pass 6 - Freeze, Reveal, And Autopsy

Freeze:

- ranked clusters;
- identity level;
- selected reduction routes;
- candidate members and widths;
- competing clusters;
- abstention if no route is sufficiently concentrated.

Only then reveal the result and grade exact literal, canonical box, boxed
VTRAC, ordered lane, pair/fragment, and no-match separately.

### Route Decomposition Receipt

The T002 examples require one additional receipt for every proposed
extraction:

| Stage | Required Record |
| --- | --- |
| Raw source | Exact string, coordinates, clock, literal pattern, and identity level |
| Reduction | Predeclared removed draw/digits, mirror policy, direction, scope, and every residual |
| Reinforcement | Vertical, horizontal, temporal, or cross-variant support with lineage de-duplication |
| Auxiliary selector | Due pair/combo, sum, position, or other external criterion and its own candidate set |
| Candidate former | Exact members, box expansion, ordered-VTRAC expansion, permutations, and total width |
| Action | Analytical-only, frozen straight, frozen box, or funded ticket |
| Result grade | Exact, canonical box, ordered VTRAC, boxed VTRAC, pair/fragment, or no match |

This receipt prevents a broad upstream pattern from receiving the credit of a
narrow downstream selector and prevents an analytically visible family from
being reported as a funded straight.
