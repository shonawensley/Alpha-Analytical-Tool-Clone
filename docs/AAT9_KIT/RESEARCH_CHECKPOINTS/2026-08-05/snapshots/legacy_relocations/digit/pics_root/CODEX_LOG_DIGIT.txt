    38 +====================

    40 +Source: tasks/New folder/digit/CORE_THEORY.txt (core methodology refresher)
    41 +
    42 +1. **Objective rephrased:** Digit Reduction isn’t “eliminate every digit from the prior draw (plus mirrors).” The real goal is to reveal a lingering **three-value** pattern (exactly three mirror class
        es) inside the long strings (R2 rows) for columns 7/6/5, guided by the prior draw digits. Dropping every candidate digit can destroy the pattern we need to keep.
    43 +
    44 +2. **Mirror classes & eliminations:** Each digit belongs to a mirror pair ({0/5, 1/6, 2/7, 3/8, 4/9}). The elimination set is the prior draw digits plus their mirrors. We only remove digits that belon
        g to that elimination set. We should search subsets of removable digits and keep the combination that best exposes a clean 3-value survivor.
    45 +
    46 +3. **Column synergy:** Evaluate columns 7/6/5 together for each elimination subset T. For each column we:
    47 +   - Remove digits in T.
    48 +   - Count surviving mirror classes and check if there are exactly three.
    49 +   - Track the actual class combinations (which triads appear) and whether they align across columns.
    50 +   - The best T maximizes the number of columns with exactly three classes, minimizes deviation from 3 in the others, and produces high “synergy” (shared triad sets) across the columns.
    51 +
    52 +4. **Proposed scoring template:** `Score(T) = 40*count3 - 5*dist_to_3 + 0.5*len_sum - 2*overlap + 10*synergy - size_T` (weights from doc). Key signals:
    53 +   - count3: how many columns hit exactly three classes.
    54 +   - dist_to_3: penalty for columns that aren’t at three classes yet.
    55 +   - len_sum: total survivor length; longer survivors imply stronger lingering patterns.
    56 +   - overlap penalty when the same mirror classes come directly from the prior draw digits.
    57 +   - synergy: intersection size of triads across columns; prioritize consistent triads (e.g., {49,16,38}) across 7/6/5.
    58 +   - size_T keeps removals minimal when competing subsets score similarly.
    59 +
    60 +5. **Tie breakers / heuristics:** Prefer subsets with higher synergy, longer survivors, lower reliance on the same mirror class as the prior draw (esp. {0/5}), and fewer eliminations. After picking th
        e best T, optionally extend the triad to alternative combinations (e.g., reintroducing a removed digit) so we track both the main 3-value pattern and plausible relatives.
    61 +
    62 +6. **LS2 (column 3/1) variant:** The same “lingering 3-value pattern” concept applies to LS2 columns (Draw4 col3 / Draw6 col1). A clean triad there is valuable evidence even if it doesn’t hit earlier
        LS1 columns.
    63 +
    64 +7. **Automation plan:** The doc outlines a deterministic algorithm:
    65 +   - Build elimination set `C = intersection of long-string digits with prior digit+mirs`.
    66 +   - Enumerate small subsets T (size ≤3).
    67 +   - Score each subset using the above formula.
    70 +8. **Analytical leverage:** Capturing the “best subset” metadata per column gives us rich features: number of triad hits, triad families, synergy scores, overlap penalties, etc. These are prime candid
        ates to add into analyzer_v2_per_item so the scoring engine can reward longer-lingering triads across columns/methods instead of heuristic-only signals.
