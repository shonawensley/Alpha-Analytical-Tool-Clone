DEEP THEORY TRAINING
====================

Source: tasks/New folder/digit/CORE_THEORY.txt (core methodology refresher)

1. **Objective rephrased:** Digit Reduction isn’t “eliminate every digit from the prior draw (plus mirrors).” The real goal is to reveal a lingering **three-value** pattern (exactly three mirror classes) inside the long strings (R2 rows) for columns 7/6/5, guided by the prior draw digits. Dropping every candidate digit can destroy the pattern we need to keep.

2. **Mirror classes & eliminations:** Each digit belongs to a mirror pair ({0/5, 1/6, 2/7, 3/8, 4/9}). The elimination set is the prior draw digits plus their mirrors. We only remove digits that belong to that elimination set. We should search subsets of removable digits and keep the combination that best exposes a clean 3-value survivor.

3. **Column synergy:** Evaluate columns 7/6/5 together for each elimination subset T. For each column we:
   - Remove digits in T.
   - Count surviving mirror classes and check if there are exactly three.
   - Track the actual class combinations (which triads appear) and whether they align across columns.
   - The best T maximizes the number of columns with exactly three classes, minimizes deviation from 3 in the others, and produces high “synergy” (shared triad sets) across the columns.

4. **Proposed scoring template:** `Score(T) = 40*count3 - 5*dist_to_3 + 0.5*len_sum - 2*overlap + 10*synergy - size_T` (weights from doc). Key signals:
   - count3: how many columns hit exactly three classes.
   - dist_to_3: penalty for columns that aren’t at three classes yet.
   - len_sum: total survivor length; longer survivors imply stronger lingering patterns.
   - overlap penalty when the same mirror classes come directly from the prior draw digits.
   - synergy: intersection size of triads across columns; prioritize consistent triads (e.g., {49,16,38}) across 7/6/5.
   - size_T keeps removals minimal when competing subsets score similarly.

5. **Tie breakers / heuristics:** Prefer subsets with higher synergy, longer survivors, lower reliance on the same mirror class as the prior draw (esp. {0/5}), and fewer eliminations. After picking the best T, optionally extend the triad to alternative combinations (e.g., reintroducing a removed digit) so we track both the main 3-value pattern and plausible relatives.

6. **LS2 (column 3/1) variant:** The same “lingering 3-value pattern” concept applies to LS2 columns (Draw4 col3 / Draw6 col1). A clean triad there is valuable evidence even if it doesn’t hit earlier LS1 columns.

7. **Automation plan:** The doc outlines a deterministic algorithm:
   - Build elimination set `C = intersection of long-string digits with prior digit+mirs`.
   - Enumerate small subsets T (size ≤3).
   - Score each subset using the above formula.
   - Keep the best T as the box’s “goal-aware” reduction and store the resulting triads per column, the synergy flags, and the elimination proof (which digit removal produced it).

8. **Analytical leverage:** Capturing the “best subset” metadata per column gives us rich features: number of triad hits, triad families, synergy scores, overlap penalties, etc. These are prime candidates to add into analyzer_v2_per_item so the scoring engine can reward longer-lingering triads across columns/methods instead of heuristic-only signals.

Source: tasks/New folder/digit/digit_training_notes.txt (stability + research checklist)

1. **Box identity via R2:** Every reduction “box” is keyed by (area, section, set, draw, col, method, mode) with R2 as the canonical identifier. R2/R4/R6/R8 show the same digit multiset with different run segmentations. Cross-box survival (same R2 string appearing in multiple boxes) is premium evidence.

2. **Intra-box stability metrics to compute per box:**
   - `earliest_step_*`: first step where exact/vtrac/drop/family classes appear.
   - `persistence_*`: number of steps (R2→R8) where each class persists.
   - `final_presence_*`: whether the class survives at R8.
   - `drop_digit_mode` and its stability across steps.
   - `dup_density`, `residual_purity`, `column_span`, `set_echo`, `variant_echo`, `method_consensus`.
   These match the detection classes already logged in Analyzer V2 and should be first-class scorer inputs.

3. **Deep research checklist (per state/date bundle):**
   - Verify training set manifests contain analyzer_v2 files plus overlay artifacts (`winner_map`, `winner_flags`, `winner_stamp`).
   - Align overlay ↔ flags ↔ per_item via the shared key (area, section, set, draw, col, method, mode); overlay highlights must trigger the same `dr.win_*` flags, and earliest-step data must match.
   - Only adjust weights after alignment; weight priority order is exact > vtrac > drop > family, with stability bonuses (persistence/residual_purity) if winners rank too low.
   - For false tops, identify which features inflated them (e.g., late-only emergence) and add clutter penalties.

4. **Recency experiments:** Use Set1/2/3 tags to test whether eliminating Set2 digits first isolates the winner earlier, and whether families echo from Set3→Set1. If so, add a recency bonus when families persist across sets.

5. **Deliverables per deep-research pass:** Document top candidate families with tags (earliest_step, column_span, variant_echo, set_echo, dup_density, drop_digit_mode), propose weight tweaks, and log any missed-detection tickets with precise windows + detection fixes.

6. **“Good looks like” after tuning:** Per-item rows that match overlay hits should rise in _top_candidates because they combine early exact/vtrac evidence, multi-column span, variant echo, good residual purity by R4, and (optionally) set echo; false positives should drop once clutter penalties apply.

ANALYTICAL CONCLUSIONS
======================

Based on the current-state docs plus the deep-theory/training material, these are the most powerful insights we need to preserve and measure during upcoming implementations and example reviews:

1. **Goal-aware triad detection**
   - The Ontario example makes it clear: elimination logic must *search* subsets of prior-digit mirrors to expose the best 3-value survivors instead of blindly deleting everything in the elimination set.
   - Action: ensure analyzer_v2 features log the chosen elimination subset, resulting triad classes per column, and the synergy score so we can validate that LS1/LS2 triads are being surfaced in per_item/top_candidates.

2. **Intra-box stability metrics are the key scoring levers**
   - `earliest_step_*`, `persistence_*`, `final_presence_*`, `dup_density`, `residual_purity`, and `drop_digit_mode` directly encode how early and how confidently a box held the winner family.
   - Action: verify these metrics exist (or add them) in per_item CSVs and wire them into the scoring weights (exact > vtrac > drop > family). Use them as primary diagnostics when reverse-engineering new runs.

3. **Cross-evidence echo must be measurable**
   - The training docs repeatedly stress column span (7/6/5), set echo (Set2/Set3), variant echo (Midday/Evening/Combined), and method consensus. These need dedicated fields so we can ask “did the same triad show up in Set2 yesterday?” or “did both Midday and Combined confirm the VT family?”
   - Action: confirm analyzer outputs capture these counts and that overlays keep the same identity keys so we can join and audit them per run.

4. **Overlay ↔ per_item alignment is non-negotiable**
   - Every tuning session must start by joining `winner_flags` onto per_item/top_candidates to check that `dr.win_*` matches the overlay. If this alignment fails, we halt before touching weights.
   - Action: bake this acceptance test into our workflow whenever we run new examples; log proofs in the training log.

5. **Recency and one-run drop scenarios are strategic differentiators**
   - Set2/Set3 context reveals if a family was “aging” and should earn a bonus; one-run drop (split-by-single-value) is often the mechanism that exposes the exact triple. Both must be logged and weighted.
   - Action: during future runs, explicitly check whether winners required drop_exact/drop_vtrac or showed up in Set2/Set3; add weight nudges or detection patches as needed.

6. **Bundle hygiene & documentation**
   - Analyzer V2 + overlay + training JSON produce everything needed for AI review. Obsolete files (legacy `digit_reduction_scores.csv`) should be removed to avoid confusion, and every bundle should be summarized in `AAT9_Digit_Training_Log.md`.
   - Action: keep the training log updated after each example sweep so insights/weight tweaks don’t get lost between sessions.

7. **Reverse-engineering playbook**
   - When we run new states/dates, the checklist is: confirm bundles/manifests; join overlay flags; audit earliest/persistence metrics; note whether triads align across columns/variants; record weight or detection adjustments.
   - Having this playbook lets us scale across many Excel dates without re-deriving the process.

These conclusions form the guardrails for the next implementation phase: any code change or scoring tweak should either add the above telemetry, verify it, or leverage it directly so the Digit Reduction tool stays practical yet maximally powerful for isolating next winners.
