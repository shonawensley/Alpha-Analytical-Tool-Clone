1) “Consensus” means two different things in this project

A. String‑table consensus (R2/R4/R6/R8)

Definition: in the string tables, consensus happens when the right‑most “tail boxes” (Columns 1 or 2) in all four rows (R2, R4, R6, R8) collapse to the same 1–2 digit substring (e.g., 7/7/7/7, 44/44/44/44). This is the “R‑consensus” used by Stable/Boxed logic, and it’s a strong finishing signal in your training.

Why it matters: you give bonus/weight to patterns that land in a consensus column; short tail stubs (1–2 digits) are especially meaningful.

B. Positional cross‑variant consensus (tracker)

Definition: in the positional tool, consensus means a digit is Top‑3 in the same position across ≥2 of Combined/Midday/Evening (2‑way or 3‑way alignments). Think “alignment across variants,” not string‑table collapse. This is exactly what your positional spec describes and what the Cross‑variant pressure summary shows.

Naming to avoid confusion:

Use “R‑Consensus” (or “Table Consensus”) for the R2/R4/R6/R8 tail‑box collapse.

Use “XVAR Consensus” for tracker alignment across Combined/Midday/Evening.
These labels mirror your training and keep the two concepts crisp in the UI, tags, and logs.

2) What the positional tracker is computing (and how it maps to your spec)

Core grid (per variant): for each position P1/P2/P3, compute draws‑since for digits 0–9, take Top‑3, render as a 3×(P1|P2|P3) grid. Yellow cell = the digit, left cell = DS (draws‑since). The red digit style is a hard‑due cue gated by thresholds.

Hard‑due thresholds: default 55 for Combined, 40 for Midday/Evening; that’s the “turn the digit red” rule your doc and work log captured when the tracker was designed.

Cross‑variant pressure and tags: the analyzer attaches small, stackable signals—alignment (2‑way/3‑way), mirror echo, double‑pressure, and swap echo—so you can read the same “cues” you were marking by hand.

Shortlist: it builds a small set of straight candidates (typically Top‑2 per slot, capped around 8–12) and tags each with ranks per position, root, V‑TRAC index, and the alignment/mirror/double cues. This is exactly the “PPA” (Positional Pressure & Alignment) behavior outlined in your blueprint.

## Key terms (so we never mix concepts)

- **R‑Consensus (Tables)** — in the string‑tables, R2/R4/R6/R8 *tail boxes* all collapse to the same 1–2 digits. Use only on table‑aware pages (Stable/Boxed/Winners).  
- **XVAR‑Consensus (Positional)** — a digit appears Top‑3 in the **same position** across ≥2 variants (C/M/E). That’s the consensus you see in the **Cross‑variant summary**.

In the tracker UI we only use **XVAR‑Consensus**. If a doc mentions “consensus” without “R‑”, assume XVAR.

## How to read the grids (90‑second play)

1) **Anchor on Combined.** It usually exposes the strongest extremes.  
   - Rank 1 DS should be the largest in its column (monotone non‑increasing Rank1→3).
2) **Scan echoes in Midday/Evening** for the same digit (or its **mirror** 0↔5,1↔6,2↔7,3↔8,4↔9).  
   - Exact matches add **XVAR‑Consensus**; mirrors add a small **Mirror‑Echo**.
3) **Watch double‑pressure.** If a digit (or its mirror) holds Top‑2 in **two positions**, doubles are “live” for that digit.  
   - Pair that with your **Due Doubles** board to decide when to push straights vs boxed.
4) **Use the shortlist, not your head, to permute.** The engine already computes Top‑2 baskets per position → small straight list with tags (TOP1x2, XVAR‑Cons, Mirror, V‑TRAC index, Root).
5) **Compound with Aux:**  
   - **Pairs**: If 1–6 is **RED**, a P2 basket {1,6} tightens boxed and points the straight.  
   - **V‑TRAC**: When an index is overdue, intersect its boxed family with the **position masks** you see.  
   - **Sums/Root**: Use as soft filters; tags show when a candidate agrees.

# AAT9 – Positional Tracker Reader (Operator & AI Cheat‑Sheet)

**What it is.** A draws‑only indicator that shows the three most‑due digits by position (P1/P2/P3) for each variant
(Combined, Midday, Evening). It’s orthogonal to Pairs/V‑TRAC/Sums: those tell you *what* relates; this tells you
*where* the pressure sits. :contentReference[oaicite:2]{index=2}

---

## 1) How to read the grid

Each variant panel is a 3×(P1|P2|P3) table:
- Left sub‑cell = **DS** (draws‑since), right sub‑cell = **Digit** (yellow badge).
- **Hard‑due** digits render red inside the yellow badge (default thresholds: Combined ≥ 55; Midday/Evening ≥ 40).
- Rows are **Rank 1 → 3** by DS (monotone non‑increasing down the column is a basic invariant).

**Quick invariants**
- Rank order: DS must not increase from rank 1→2→3.
- Hard‑due: any red digit respects the threshold in effect for its variant.

---

## 2) Tags and what they mean

**XVAR‑Consensus**  
Same **digit** is Top‑3 in the same position across ≥2 variants (e.g., `C+M`, `C+E`, or `C+M+E`). This is the strongest
positional confirmation. (Do *not* confuse with *R‑Consensus* in string tables; that’s a tail‑box collapse in R2/R4/R6/R8.)  
**Mirror‑Echo**  
A digit’s mirror (0↔5, 1↔6, 2↔7, 3↔8, 4↔9) supports the same position in another variant.  
**Double‑Pressure**  
A digit (or its mirror class) shows in **two positions**. Stronger if Due Doubles is active.  
**Swap‑Echo**  
Digit appears in an adjacent position across variants (e.g., P2↔P3). Useful rhythm cue.

> Naming hygiene: we always say **“XVAR‑Consensus”** here; reserve **“R‑Consensus”** for string‑table tail‑box collapse
> used by Stable/Boxed logic. This keeps narratives crisp across modules.

---

## 3) Cross‑variant pressure summary

Below the grids you’ll see, for P1/P2/P3, the **Digits** with:
- **Score** (small, additive, transparent components),
- **Hits** (which variants contributed: `C#1, M#2 …`),
- **Tags** (XVAR‑Cons, Mirror‑Echo, Double‑Pressure, Swap‑Echo).

Use this to decide which position(s) are “locked” and which remain open.

---

## 4) Positional shortlist (how the tool jumps to straights)

We take Top‑2 per position (configurable), build a **small Cartesian product** (capped ≈ 8–12), and tag each combo with:
- **Ranks** (e.g., `2-2-3`),
- **Root** (digital root), **V‑TRAC index** (annotation only),
- **Tags** (XVAR‑Cons, Mirror‑Echo, Double‑Pressure, Swap‑Echo).

Keep it draws‑only here; use BA, Sums, and V‑TRAC to **compound** (not to drive) the shortlist. :contentReference[oaicite:3]{index=3}

---

## 5) Fast operator workflow (daily)

1. **Control Center**: triage by BA status & Doubles Watch; glance at the **PP heat** badge per state/variant.  
2. **Open Aux → Positional**:  
   - Look for **2‑way or 3‑way XVAR‑Consensus** in the same position.  
   - Note any **Double‑Pressure** (two positions lighting for the same digit/mirror).  
3. **Shortlist → Compound**: cross‑check with Pairs RED/BLUE and the day’s Sums/Root band.  
4. **Log**: record P1/P2/P3 hits alongside winners for later learning (simple boolean columns are enough).

---

## 6) Sanity checks (no backtest needed)

- **Grid monotonicity** per position (DS down the ranks).  
- **Hard‑due coloring** respects thresholds.  
- **XVAR Hits** = count of variants where the exact digit is in Top‑3 for that position (mirrors do not inflate Hits).  
- **Shortlist ranks** match the grid’s per‑position ranks.

- Pairs window must be deep enough (≈360) or RED/BLUE won’t make sense across modules. If pairs look “quiet,” print the
