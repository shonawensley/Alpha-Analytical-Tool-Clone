1) What the feature is (precise language)

Hidden‑Behind / Shift‑Scan (HBSS)
A small transform engine that searches for pattern invariants under controlled single‑digit perturbations:

Mask one position (treat as wildcard) → check if the remaining two‑digit pair reveals a stable family/pattern.

Mirror one digit (0↔5, 1↔6, 2↔7, 3↔8, 4↔9) → see if a pattern emerges.

Rotate/Shift digits (L/R by 1) → reveal lane/position‑dependent patterns.

Substitute a single position through 0–9 (bounded, not brute force) to detect pair‑anchored stability (“the pattern holds regardless of the third digit”).

HBSS doesn’t “force” a hit; it explains that a pattern would be stable if a single noisy digit were neutralized (mask/mirror/shift). This is exactly what your logger highlights visually in the grids—now we formalize it so Stable can score and rank it.

5) “Pair‑anchor” rule (the heart of “hidden behind a digit”)

The simplest, robust rule that matches what you described:

A pattern is “hidden behind a digit” if the two fixed digits of the string (the internal pair) consistently classify to the same Stable family across a set of single‑digit perturbations at the third position.

Translated:

For each position p ∈ {0,1,2}
Keep the other two digits fixed; vary the digit at p using one of:

a mask (“wildcard”),

a mirror at p,

a small candidate set (often {mirror, current} or {current, ±1, mirror}),

or a short 0..9 pass (optional; cap for speed).

If most transformed strings map to the same Stable family label, count it as HBSS evidence for that combo.

If require_pair_anchor=True, only award evidence when the two fixed digits stay in order (or you can allow ab_ and _ab forms—pick one and document it).

This is exactly the “the pattern is there if you neutralize one digit” intuition—now encoded as a tight, testable rule.

The weather analogy (fully fleshed out)

“It’s dark and cloudy, so I think it’ll rain” is a weak heuristic.
Meteorologists stack many instruments: satellite imagery, Doppler radar, dew point, barometric trend, wind shear, frontal boundaries, ensemble models. When multiple independent sensors align, they issue a Watch or Warning with a quantified confidence.

We’re doing the same with string patterns:

Simple look (“dark & cloudy”) → single cues like “a big gap” or “one exciting streak.”

Stacked instrumentation → multiple independent, well‑defined signals that line up at once.

Mapping the instruments
Weather “sensor”	Our “sensor” (examples)	What it contributes
Satellite / radar	Remaining‑pairs foundation (27–29 method)—structural coverage of pairs before we even talk sums or mirrors	Narrows the search to structurally valid candidates; gives a base universe you can actually play
Dew point / humidity	Floating digits (dryness)—digits absent in the recent window	Recency pressure—when a dry digit coincides with structure, we lean in
Barometric trend	Root‑sum / digital‑root gap (hazard toward a due root, e.g., RS 7 or 3/6/9 cluster)	Directional pressure; we prefer candidates whose RS matches what’s due
Front boundaries	Cluster/box context (R2/R4/R6/R8; V‑TRAC families)	Where the storm “lives” inside the grid—boxed + straight interactions and cluster motion

Reverse‑engineering wins (how we learn from real examples)

For each winner we log:

What pattern won (and where it sat in R2/R4/R6/R8; boxed vs straight; cluster lineage).

Which signals were present at the time (structure, due roots/sums, floats, mirrors, family pressure, occlusion/shift detections).

Lead time (how many draws between ALERT and the hit).

Environment (Combined/Midday/Evening context; inter‑variant echoes).

Counterfactuals (what nearly won; which signals were misleading).

Those logs feed two outcomes:

Portable feature functions (pure, unit‑tested) that any tool can call.

Weights & thresholds for the integrated scorer, tuned to prioritize profitability (play less, with higher confidence).

The evidence stack → a single, explainable score

Signals. Each signal is a pure function that returns {present: bool, strength: float, tags: set, window: int, lead_time: estimate}.

Weights. Start conservative. Structural signals (e.g., remaining‑pairs coverage) earn base weight. Situational signals (mirror, floats) nudge. Statistical/hazard signals (root‑due, sums bands) calibrate timing.

Score.
StateScore = Σ (weight_i × strength_i) with gates:

Gate 1 (Structure): candidates must satisfy structural coverage (e.g., all three internal pairs still “out”) to be considered.

Gate 2 (Stack): require ≥N independent signals to be present (e.g., structure + root‑due + one of {mirror, floats, extreme pattern}).

Gate 3 (Risk): use per‑state hazard baselines to avoid over‑firing during noisy regimes.

Ladder.

OFF: score < 2 (or stack < 2 signals)

WATCH: score ≥ 2

ALERT: score ≥ 3 (stack ≥ 3 signals)

QUALIFIED FOR WAGERING: score ≥ T (e.g., 4–5) and passes bankroll/risk constraints (below)

The BA layer already uses a similar OFF/WATCH/ALERT notion and caps candidates (e.g., top‑12 with tags) for readability; the integrated scorer should preserve that UX because it trains the operator’s eye while staying explainable.

Profit focus: spend less, win more

Expense management is a feature. The easiest profit lever is not betting when confidence is low. We enforce this with:

A play/pass gate at “Qualified for Wagering.”

Ticket caps tied to confidence tiers (e.g., 2, 6, 12).

Cooldowns after a miss to prevent churn.

Confidence tags drive stake sizing. Keep it simple at first:
Green (Qualified), Amber (ALERT), Gray (WATCH/OFF).

Why “more detail” (not less) is the right call

The more precisely we describe how a pattern forms and what environmental conditions surround it, the more levers we have to (a) score correctly, (b) generalize across states/variants, and (c) keep the system powerful even without ML. Detail does not mean noise: every feature must be measurable, portable, and tested against real winners.

Portability: reusing working ideas across tools

Feature spec (one page per signal):

Name & purpose. (e.g., Hidden‑behind‑digit exposure.)

Inputs. draw strings + window; optional variant context (Combined/Midday/Evening).

Method. deterministic algorithm (e.g., shift/unwrap/occlusion check).

Output. {present, strength, tags} + minimal provenance (what it saw).

Compatibility. Which tools can consume it (Stable, V‑TRAC, Aux/BA).

Tests. Three real winners where it fired correctly and three where it declined to fire.
