Why this plan is correct (in one paragraph)

Your NaNs come from joining winners on a string canonical (e.g., 758 → "578") against spotlight rows that carry extended substrings (e.g., "007788")—there’s no equality, so the merge fails. Stable’s real unit of meaning is V‑TRAC family. If we (1) compute each winner’s family_id, (2) pick the best row for that family from the scores table (Combined‑first, then best score), and (3) make the spotlight write both the raw extended substring and the family tags, every join becomes deterministic and robust to extended digits and leading zeros.

What will change (high‑level)

winners_enrich.py

Reuse stable.canon / stable.digits_only (single source of truth).

Compute family_id for each winner; merge by family (not string canonical).

Build a per‑family “best row” from scores.csv (Combined‑first, else highest score).

Add evidence_status = ok / no_family_id / no_row_for_family (so the UI never shows naked NaNs).

winner_family_spotlight.py

Keep your extended substring (call it raw_canonical).

Also emit family_canonical_3v (a 3‑digit representative) and family_id for each row.

Keep the original Canonical column for backward compatibility.

metrics.py

Detect winners by family, not string equality.
