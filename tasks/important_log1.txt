• Your “hybrid model” framing is solid, and it’s the safest/most practical way to build something real:

  Thoughts on rules/scoring first → ML later

  - Building a strong system without ML forces you to define clean contracts: inputs (tables/draws), evidence (tool outputs), and decisions (candidates + play/no‑play). That’s exactly what we’re doing with sharepacks + run
    reports + summarizers.
  - A rules/scoring aggregator is the right first “superbrain” because it’s:
      - Debuggable (you can point to evidence and say “this feature caused this boost”).
      - Data-light (doesn’t require thousands of labeled examples to be useful).
      - Leakage-resistant (you can enforce “D‑1 only” inputs explicitly).
  - ML becomes valuable after you have stable feature vectors and labels. In this project, ML should start as a calibrator/weight tuner, not the core brain:
      - Learn weights for the signals you already trust (Stable/DR/VTRAC/HotZones/Aux).
      - Learn a play/no‑play classifier (profitability gating) and/or a cost‑sensitive chooser (perm-only vs VT-box).
      - Stay interpretable at first (logistic regression / shallow tree) so it doesn’t become a black box that’s hard to correct.

  That approach matches your goal: “unstoppably strong without ML; ML later only adds incremental edge.”
