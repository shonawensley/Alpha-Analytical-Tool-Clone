2) Four winner types (add V-TRAC straight as a fourth)
Totally agree. The natural hierarchy is:


Exact straight (digits + order)


Exact boxed (digits any order)


VT-boxed (“winner is in this VT index; 8 combos”)


VT-straight (“winner follows a specific VT straight lane – order clue”)


We now have the pieces to support all four in a central winners module:


Exact straight / boxed – Stable’s winner_hits flags + spotlight is_exact_*.


VT-boxed – Stable is_vtrac_boxed + winner_hits[w]["vtrac_boxed"], and the V-TRAC analyzer’s index log.


VT-straight – we can capture this two ways:


In Stable:


row-level score_vtrac_straight and vtrac_straight_hits in compound tell us which canonicals are part of VT-straight sequences;




In V-TRAC analyzer:


that big “VT straight reference chart” you mentioned (or index-level straight lanes) can be encoded in vtrac_compact_report.{csv,json} as “this index’s straight lane includes combinations: …”






When we build the central winners module, we can explicitly log e.g.:
"winner_classes": {
  "733": {
    "exact_straight": true,
    "exact_boxed": true,
    "vt_boxed": true,
    "vt_straight": true
  }
}

based on:


Did any tool mark exact?


Did V-TRAC index map align?


Did Stable / V-TRAC confirm a straight-lane pattern for that winner?


So: we don’t need to jam more VT logic into Stable now; instead we’ll make sure the winners module reads:


Stable’s winner_hits + vtrac_straight_hits,


V-TRAC analyzer’s per-index winners log + straight-lane definitions,


and uses that to label each winner with those 4 categories.
