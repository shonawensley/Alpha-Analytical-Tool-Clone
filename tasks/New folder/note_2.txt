•	win_exact, win_vtrac, win_drop_exact, win_drop_vtrac, win_3val_exact, win_3val_vtrac (+ earliest step fields).
Weights: exact = 1.00, vtrac = 0.95, drop = 0.65, family = 0.45.
Rationale: Combined often yields V TRAC before an exact shows in a native variant—don’t underweight it.
B. Box level stability (new)
•	box_stability_r2r4 = fraction of tokens in the R2 box that belong to the candidate family AND reappear in R4 of the same cell.
•	box_span = count of ladders (R2/R4/R6/R8) where the family is present.
Why: What you called “stability support scoring”—it’s visible across the samples.
C. Set lag / recency gradient (new)
•	set_earliest ∈ {1,2,3} and set_lag = 1 - set_earliest/3 (higher is better).
Why: When Set2/3 pre signals and Set1 tightens, candidates deserve a boost.
D. Cross variant consensus (new)
•	variant_support ∈ {C only, C+M, C+E, M+E, all three}.
Why: Combined+one native is the most common winning path in these overlays.
E. Pair backbone strength (new)
•	pair_density(a,b) for the two strongest pairs inside the 3 value set, computed as “count of pair occurrences across 7/6/5 columns within R2” (normalized).
Why: Pairs like 78, 18, 57/58 are the day’s backbone; inside a state they clearly form clusters.
F. Doubles / drop one context (new)
•	double_flag (any digit has multiplicity 2).
•	drop_run_length (length of the contiguous run removed when drop_* fires).
Why: Doubles win often through drop_* exposure; longer runs are stronger evidence.
G. Family saturation (new)
•	local_family_density = % of tokens in the cell’s R2 line that belong to the candidate’s 3 value set (counts duplicates).
Why: You can see whole R2 stretches dominated by, say, {7,5,8} even when no exact window is present.
H. Optional “pair of the day” prior (experimental)
•	global_pair_prior(a,b) pulled from a simple day level histogram (if you want cross state awareness in an Aux layer).
Why: On this day, 78 is everywhere; a tiny nudge helps break ties.
