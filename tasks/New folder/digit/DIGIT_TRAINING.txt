  - Training prompts / investigative angles
      - Examine how Set1 (current draw) boxes isolate the winner—could earlier reduction steps (R1→R2) have captured the permutation sooner?
      - Compare Set2/Set3 contexts: if the winner appeared or nearly appeared “yesterday,” is there a feature you can add to reward that carry-over?
      - Track cross-variant alignments: when Midday and Combined share V-TRAC families, how did the analyzer weigh them?
      - Use the permutations list to hunt for near-miss digits the overlay didn’t flag and note adjustments needed.
      - Consider how 3-value reductions map to the provided V-TRAC families—should late-stage hits contribute more to the score?
      - Document how exact/vtrac/drop/3-value signals converge; note patterns you want the analyzer to prioritize next run.

      - Run reducer → Analyzer V2 → Winners overlay from Streamlit.

BASIS FOR ANALYSIS 1:
Mission (precise)
Identify and rank the next winning pattern candidates—either the exact 3 digit winner or any member of its local V TRAC family—by tracing, highlighting, and scoring evidence across all reduction ladders (steps 0→N), boxes (R2/R4/R6/R8 across cols 7/6/5), methods (A–E), datasets (Own/Combined), and time buckets (Set1 current, Set2 previous, Set3 two prior).
This keeps the goal explicit (next draw winner candidates), includes both direct & V TRAC pathways, and grounds the “how” in the ladders/boxes/methods/variants you actually analyze.
________________________________________
What counts as a “3 value pattern” here
Treat any of the following as valid 3 value structures (digits or V TRACs):
•	3 unique digits (e.g., 361).
•	2 uniques, length ≥3 (e.g., 266).
•	3 uniques extended (e.g., 336611).
•	2 uniques extended (e.g., 266666, 38888).
•	3 V TRAC digits (e.g., 693).
•	2 V TRACs extended (e.g., 64444).
•	4 concrete digits but 3 V TRAC groups (e.g., 99224466 reduces to three V TRAC buckets).
Heuristic: more digits inside a valid 3 value family ⇒ stronger evidence (e.g., 61188 > 618).
________________________________________
Detection classes (what the overlay + analyzer should tag)
Each cell/“run” is scanned—no skipped boxes. We assign the strongest class present:
1.	Exact – any 3 window matches a permutation of the winner (e.g., 059 → 590, 905, …).
2.	V TRAC – any 3 window maps to the winner’s local V TRAC index.
3.	Drop one (Exact/V TRAC) – a 3 window becomes Exact or V TRAC after removing one value from that run (handles “split by one value,” e.g., …99220… ⇒ drop one 2 ⇒ maps to the winner family).
4.	3 value family (Exact/V TRAC) – the set of digits matches the winner’s 3 value set or its V TRAC family, even when length >3 (e.g., 599000 → family of 590).
These are the categories Codex wired into the overlay, hits/flags, and analyzer scoring. They are exactly the “A–D” optimizations you asked for: no missed boxes, single value split detection, V TRAC parity, and extended length 3 value recognition.
________________________________________
Golden rules (operator guidance)
1.	Always account for V TRAC. If a draw digit is absent, treat its mirror as present.
2.	Probe “as is”; confirm “all occurrences.” “As is” preserves duplicates to reveal stability; “all” tests purity.
3.	Reward repetition & agreement: across steps (early & sustained), across cols (7/6/5), across sets (1/2/3), across methods (A–E), and across variants (Midday/Evening/Combined).
4.	Doubles matter. More copies inside the 3 value family = stronger signal (with caps).
5.	Consistency with Combined. If Own and Combined agree, confidence increases.
6.	Penalize clutter & late emergence. Too many residual digits or very late convergence reduces confidence.
________________________________________
Scoring signals (what the analyzer should compute)
(You already have most of these; ensure the weights reflect the new overlay flags.)
•	Purity / residual clarity: unique_after == 3 bonus; clutter penalty for >3.
•	Time to 3 & span: earlier collapse and longer persistence score higher.
•	Repeat across columns: count matches in 7/6/5 and in both sets.
•	Method consensus: A–E agreement, same canon / same V TRAC.
•	Cross variant convergence: Midday ∩ Evening ∩ Combined (exact & V TRAC).
•	Stability echo: same/related patterns hold in R2↔R8 boxes.
•	Doubles: bounded bonus for extra copies inside the family.
•	Winner evidence (merged from overlay flags):
o	dr.win_exact, dr.win_vtrac, dr.win_drop_exact, dr.win_drop_vtrac,
dr.win_3val_exact, dr.win_3val_vtrac + earliest step fields per type.
o	Weight exact highest, then V TRAC, then drop one, then 3 value family.
________________________________________
QA guardrails so we never “miss a box” again
•	Full sweep, two passes:
o	Pass 1: scan every numeric “run” in every cell; tag 3 windows.
o	Pass 2 (fallback): normalise characters (ASCII only), treat any E/scientific looking formats as strings, and rescan.
•	Earliest step metrics per type must always be emitted (even if no final exact).
•	Category counts in the overlay legend must match the CSV/JSON flags.
•	Drop one audit: for each hit, store drop_digit so you can spot “split by one value” cases in review.
________________________________________
Recent draw context & training bundles
•	Sets are time labeled: Set1 = current, Set2 = previous draw, Set3 = two prior (for Midday/Evening/Combined). The stamp/map JSON carries recent draws so humans and AI see the same context you see in the banner.
•	Training bundle (one stop folder) contains the analyzer CSV/JSON and winners artifacts, ready for analysis or ML. Paths and files (per state) are stable:
o	Analyzer V2 outputs land in
data/outputs/analysis/digit_reduction/<STATE>/analyzer_v2/
→ *_per_item.csv, *_own_vs_combined_delta.csv, *_top_candidates.csv, *_meta.json. 
o	Winners overlay artifacts land in

→ overlay HTML, winner_map.json, winner_hits.csv, winner_flags.csv, winner_stamp.json; the stamp can also be mirrored to the Winners logger. 
o	The reducer’s training JSON sits at
data/outputs/analysis/digit_reduction/<STATE>/training/<STATE>_digit_reduction_log.json (create the folder if missing). The analyzer can’t run until this exists. 
If a brand new state has no digit_reduction/<STATE>/… yet, run the tables pipeline first (to create the three combined CSVs), then run the raw Digit Reduction export to write the training JSON; only then run Analyzer V2. The UI guardrails we outlined keep this sequence obvious.

Minimum acceptance tests (per winner you validate)
1.	Overlay: all relevant boxes are highlighted; legend tallies = per cell spans; earliest step fields populated for every category; permutations & V TRAC family listed in JSON.
2.	Flags merge: joining winner_flags.csv onto per_item.csv lights up the same rows you saw highlighted (exact/V TRAC/drop/3 value), with matching earliest step values. 
3.	Score reaction: rows with early exact/V TRAC evidence bubble toward the top in *_top_candidates.csv; if not, adjust the weights, not the detection.

Why your revised mission is better
•	It makes the target explicit: next winner candidates, not an abstract “surviving pattern.”
•	It encodes both channels to be right: direct exact and V TRAC relatives.
•	It forces the system to trace evidence end to end (steps → boxes → methods → datasets → time), which is how you actually validate.

How to read the grid (and what to test)
Goal (analysis language): Identify the strongest winning pattern candidates, either as exact triples or V TRAC family members, and track where and how early they emerge across methods (A–E), sets (1–3), columns (7/6/5), and variants (Midday/Evening/Combined).
Primary detection passes
1.	Exact permutations — anywhere a 3 digit window equals a winner permutation.
2.	V TRAC windows — anywhere a 3 digit window belongs to the winner’s local V TRAC family.
3.	One run drop (split by a single value): if removing a single contiguous run (e.g., 00, 22, 555) within a longer numeric run reveals an exact or V TRAC window, flag drop_exact / drop_vtrac.
4.	3 value family: if all digits in a run belong to the winner’s 3 value set (exact or V TRAC set), flag family_* even when duplicates extend the pattern (e.g., 599000 → family of 590).
Cross evidence to collect
•	Earliest step a match appears (lower is better).
•	Persistence across columns 7→6→5 (more columns = stronger).
•	Set echo (Set1 vs Set2 vs Set3) — did it appear “yesterday” or “two days prior,” too?
•	Variant convergence (Midday / Evening / Combined) — do multiple datasets point to the same exact/V TRAC family?
•	Method agreement (A…E) — how many methods confirm the same candidate?
