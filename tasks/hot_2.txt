3. Minimal guard spec for _generate_guard_triads

Here’s the spec I’d hand to Codex, in plain language + pseudocode.

3.1 Where the guard applies

Only for Combined section.

Only for Set1.

Only for Draw1 (we care about the “top lattice” representing recent history).

Only for columns 1 and 2 (C1/C2).

Only when metadata.hot_zone_count >= 20 for that draw (or a similar high threshold you’ve used).

3.2 What digits to use

For a given (section='Combined', set='Set1', draw='Draw1', column_index ∈ {1,2}):

From the JSON env (TableEnv), get:

draw.draw_data for that Set1/Draw1 entry.

Map column_index back to the right position in draw_data (since it’s stored as 7..1).

e.g., if C1 is the last element in the list, and C2 is the second-last.

Let num = draw.draw_data[column_index_for_this_box] — string like "494", "858", "733".

Extract digits: d1, d2, d3 = the three chars of num that are digits.

3.3 Triads to create

For each such box:

Always create the canonical triad:

triad_main = ''.join(sorted([d1, d2, d3]))


Optionally, also create a VT-mirror triad:

For each digit d, map to its VT mirror using MIRROR_MAP (0↔5, 1↔6, etc.).

Build triad_mirror = ''.join(sorted([mirror(d1), mirror(d2), mirror(d3)])).

If triad_mirror != triad_main, include it.

For column 1 and column 2, you might also inject one “union” triad built from digits appearing in both C1 and C2 in the last couple of draws, but that’s optional. For v1, I’d stick to:

At most 2 triads per column (main + mirror).

So per state/date, columns 1–2 yield at most 4 guard triads.

Triads are deduplicated before returning.

3.4 When to mark guard_injected

In mine_evidence, when you’re processing a vertical stack (section, set, draw, column_index):

You get the set of guard triads for that stack: guard_triads.

For each triad t you consider in that stack:

guard_flag = (t in guard_triads)


Feed this into Evidence.guard_injected.

3.5 Scoring and sorting rules

In _score_evidence(e, weights):

If e.guard_injected:

Add weights.w_guard_bonus (e.g. 3.0).

Add "guard_set1" to reasons.

In aggregate() when building TopCandidateRow:

Compute:

guard_hits = sum(1 for e in evs if e.guard_injected)
literal_hits = sum(1 for e in evs if e.is_literal_draw)


Sorting order for tops:

tops.sort(key=lambda r: (
    -r.score_max,
    -r.guard_hits,    # guard-backed triads win ties
    -r.literal_hits,  # then literal draws
    -r.score_mean,
))


That way:

Triads that are:

high score,

plus guard-backed,

plus literal,

rise to the top when everything else (VT lanes, funnels) are similar.
