Part 1 — “Signal‑aware shortlist” (minimal patch that will surface cases like 989)
0) Naming (prevent Combined/confusion)

Variant keys: {"combined","midday","evening"}.

All‑Variant consensus: label as “C+M+E (All‑Variant)” in UI; never call this “Combined.”

1) Inputs the tracker already computes (reuse them)

Top‑K per position per variant (e.g., top 3 digits at P1/P2/P3 for C, M, E) + their per‑position scores and ranks.

Lane hits: which digits are hot per lane (C/M/E) at each position.

Tags already produced per digit: XVAR-Cons(…), Mirror‑Echo(…), Double‑Pressure, R‑swaps.

(From Aux cache) V‑TRAC overlay heat and Top‑5 double families (for small boosts in Part 2).

2) Candidate streams (three small generators)

All‑Variant union cartesian

For each position, take the union of top‑K digits across C+M+E (K default 3).

Cartesian product (P1×P2×P3), dedupe, cap (e.g., 48).

Repeat‑endcap

If the same digit is top‑K at both P1 & P3 in any lanes, enumerate d _ d with bridges from:

P2’s top‑K union plus any P2 digits hot in the same lane as the repeated endcaps.

This is the rule that emits 9‑8‑9 when 9 is E#1 at P1 and P3 and 8 carries Evening support.

Lane‑concordance

For each lane ∈ {C,M,E}, form a tiny set using top‑2 per position from that lane only (≤8 combos per lane).

Captures “pure Evening” / “pure Midday” patterns the cartesian step can underrate.

Keep your original TOP1×N variants; the three generators above add candidates—they don’t remove anything.

3) Transparent scoring (weights in config, not hard‑coded)

Let every candidate xyz receive a sum of simple, explainable terms:

Score(xyz) =
  w_rank * Σ_pos rank_score(pos,digit)                      [1.0]
+ w_xvar * Σ_pos xvar_hits(pos,digit)                       [2.5]
+ w_echo * Σ_pos mirror_echo(pos,digit)                     [1.0]
+ w_dblp * Σ_pos double_pressure(pos,digit)                 [1.0]
+ w_rep  * 1{P1==P3} * 0.30 * (score(P1,d)+score(P3,d))     [0.3 scaled]
+ w_lane * 1{lane‑pure} * 0.15 * base_score                 [0.15 scaled]
+ w_root * root_weight(xyz)                                 [0.4]
(+ small V‑TRAC nudges in Part 2)


Defaults (put in core/aux_config.py):

POS_SHORTLIST_K_TOP = 3
POS_SHORTLIST_MAX   = 16      # rows shown
POS_SHORTLIST_CAP   = 64      # internal candidate cap
POS_SHORTLIST_WEIGHTS = {
    "w_rank": 1.0, "w_xvar": 2.5, "w_echo": 1.0, "w_dblp": 1.0,
    "w_rep": 1.0,  "w_lane": 1.0, "w_root": 0.4,
    "w_vtrac_index": 0.8, "w_vtrac_family": 0.6   # used in Part 2
}


Why this works:

XVAR lets C+M+E together move the score—this is what pulls 989 up when 9 is Evening #1 at both ends and 8 has Evening/Combined support.

Repeat‑endcap and lane‑concordance bonuses are small but decisive in the exact scenario you pointed out.

Mirror‑Echo & Double‑Pressure remain additive (your current tags now “count,” instead of being printed and ignored).

Part 2 — Light V‑TRAC boosters (self‑contained; no redesign)

These do not gate; they add small weight only when Aux says “warm.”

Index heat (+w_vtrac_index)

Map xyz → vtrac_index (you already compute).

If that index is in the Top‑10 overdue or on Repeat‑Watch for the same state/variant, add w_vtrac_index.

Double family presence (+w_vtrac_family)

If xyz is a double, find its family (e.g., 0/5–4/9); if that family is in the Top‑5 column strip for that state row in Control Center, add w_vtrac_family.

Variant‑aware nudge (optional)

If a combo’s strongest lane (where it got most of its per‑position xvar hits) matches the lane where the index is hot, add half of w_vtrac_index.

Keep the defaults small (0.8, 0.6); they should never drown the string‑evidence signals. This matches your “auxiliary features enhance, not dominate” rule.
