A. What broke and why it was hard to see

Two V‑TRAC APIs now exist by design:

Canonical modules/vtrac_reference.py (lean; no VTRAC_DISPLAY/BOXED_LABEL_LOOKUP) to support newer Winners/Analyzer paths.

Legacy/staged reference (rich; has BOXED constants) that Aux still needs.

During cleanup, the rich legacy file was moved/archived, while refactored Aux bootstrap still points to the old folder. At runtime:

Early imports may succeed, but lazy imports inside analyze_pairs/helpers re‑import modules.vtrac_reference later and bind to the canonical one. That’s why you saw both “works / fails” behaviors depending on timing.

Because Aux’s helpers are coded to soft‑fallback on import failure (to avoid crashing the app), the user‑visible message devolved into “No state data files found”, which misdirected attention to CSV paths even though the real cause was import binding.

B. The minimal, safe fix (5 tiny changes)

Goal: Make Aux deterministically bind to the staged legacy package for the entire analysis window, and make the staged package self‑contained so it won’t hop to the project module even if someone changes sys.path later.

The patches below are deliberately small and reversible. They do not touch V‑TRAC/Stable/DR/BA logic or the combined tables pipeline. Aux continues to use data/cleaned/*_draws.csv.

1) Keep staged working package first for the entire Aux run

File: src/app.py

Strengthen the _aux_working_first() context:

insert(0, _AUX_WORKING_ROOT) on enter and restore the entire sys.path on exit.

Evict sys.modules["modules"] and its children on enter; restore any saved binding on exit.

Wrap the whole Aux cached_aux_analysis(...) body in _aux_working_first() (not only the import lines) so that late imports inside analyze_pairs also resolve to the staged package.

Your screenshot shows Cursor already made a version of this change. Keep it. Verify the finally restores sys.path[:] = old_sys_path and re‑inserts the previous modules binding if it existed.

2) Make staged imports relative so they can’t hop away

Files (staged package only — the ones under scripts/auxiliary/working/modules/):

In any staged module that currently says
from modules.vtrac_reference import ...
change to
from .vtrac_reference import ...

In staged modules that import siblings (e.g., analyze_pairs, vtrac_utils), prefer
from .analyze_pairs import ... (relative)
instead of relying on ambient sys.path.

This locks the staged package to itself and prevents it from “finding” the project’s canonical modules package by accident later.
