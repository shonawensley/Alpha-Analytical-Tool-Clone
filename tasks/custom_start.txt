AAT9 — Positional Tracker & Aux Layer: Context + Do‑First Checklist for Codex
What broke & why (1‑page summary)

Pairs coloring drifted because Aux was still calling calculate_overdue_pairs() with only the last 100 draws, so RED/BLUE thresholds (107/71 for repeating; 56/37 for non‑repeating) could never be reached. We lifted the analysis window to 360 and made it a constant so the thresholds register correctly.

Positional tracker UI: the older Aux expander expected a simple top‑k per position table; during refactors we began returning richer objects (scored digits, tags, etc.). The Streamlit code was updated to a Tracker grid (3 ranks × P1/P2/P3) that mirrors the operator mockup, but any lingering calls that assume a .dict() (Pydantic) API—or that import the positional module before staging—will throw errors like 'NoneType' object has no attribute 'dict'. The fix is consistent imports + reading dataclass fields directly (or a to_dict() shim).

V‑TRAC staging vs canonical API: we restored the staged legacy V‑TRAC reference (for Aux) and added a canonical shim for other pages. Aux must stage the working modules first so VTRAC_DISPLAY/BOXED_LABEL_LOOKUP are present; we added a smoke script + staging manifest to catch drift.

Why the positional tool matters: it’s the missing “where” signal (per‑position pressure) that composes with Pairs, Sums, V‑TRAC, Doubles, and BA. We already documented how to compute/render it and how to use it operationally (PP score, consensus/mirror/double pressure).
