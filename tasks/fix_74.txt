




You’re right to think this is a “wiring” issue. In Streamlit a totally blank page (no red error box, no sidebar, no header) almost always means:

the script started successfully, but nothing wrote to the page because the entrypoint that renders the UI isn’t being called anymore.

Given the edit history you shared (inline block surgery around src/app.py, duplicated/removed expander blocks, attempts to splice near if __name__ == "__main__":, stray literal \n, smart quotes, etc.), the most likely failure modes are:

What most likely happened

The entrypoint call got removed or skipped.
Many Streamlit apps keep rendering inside a function like main(), show_app(), or a router. If the bottom-of-file block:

if __name__ == "__main__":
    main()     # or show_app(), run(), etc.


…was deleted, moved above the function definition, or guarded by a condition that’s now false, the script runs and emits nothing → blank page.

Early short‑circuit before rendering.
An unconditional return, st.stop(), or a try/except that swallows an exception at the top can end execution before any st.* call is reached, again leaving a blank page.

Curly quotes / stray characters broke a conditional.
Earlier you had \n literals and an en‑dash in the new expander title. If the same kind of invisible character landed on or near the if __name__ == "__main__": line or its indent, Python will happily parse a different string or skip the block. That would compile fine and still produce no UI.

The dev overlay import is now top‑level and failing silently.
If you wrapped imports in a broad try/except: pass near the top, an ImportError or NameError could be swallowed and the script then exits early with no UI calls.

Fast triage (2–3 minutes)

Set-Content sanity.py 'import streamlit as st; st.title("Sanity OK")'

If this shows a “Sanity OK” page, Streamlit is healthy and the blank page is your app code path.

Check your entrypoint exists in src/app.py.

Select-String -Path src/app.py -Pattern 'def main\(|def show_.*app\(|def run_app\('
Select-String -Path src/app.py -Pattern '__name__\s*==\s*"__main__"'


If you don’t see a line with __name__ == "__main__", that’s the bug.

If you see it, open the last ~60 lines and confirm the call:

You should see something like:

This won’t catch logic skips, but it does confirm the file parses.

Surgical “get me back on screen” fix

If step (2) shows the entrypoint is missing or not calling anything, add this safe rescue block at the very bottom of src/app.py (below everything else):

# --- RESCUE BOOT: keep at end of file ---
def _rescue_boot():
    import streamlit as st
    st.set_page_config(page_title="Alpha-Final Analytical Tool", layout="wide")
    st.title("Alpha‑Final Analytical Tool")
    st.write("✅ App booted (rescue path). If you can read this, the main render call was being skipped.")
    # Optionally: render a minimal home or quick links here so you can keep working.

if __name__ == "__main__":
    try:
        main  # or show_app / run_app, depending on your app
    except NameError:
        _rescue_boot()
    else:
        try:
            main()  # or show_app() / run_app()
        except Exception as e:
            _rescue_boot()
            import streamlit as st
            st.error(f"Main render raised: {e}")
