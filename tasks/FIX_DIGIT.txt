Keep strings as strings in memory
Wherever we build rows (reducer logs → analyzer), force:

val = step.get("value", "")

Before writing CSV

df["value"] = df["value"].astype(str)

When reading CSV back

pd.read_csv(path, dtype={"value": "string"})


This removes scientific notation and protects leading zeros and * markers.

B. The method, restated cleanly (so the code can follow it)
“Digit reduction” in one sentence

Use the most recent draw digits to reduce the long strings, watching for a 3‑value pattern that survives, repeats, and converges (exactly or via its V‑TRAC mirrors) across reduction steps, boxes (R2/R4/R6/R8), and variants (Midday/Evening/Combined).

Two legitimate ways to “account for” a draw digit

Remove all occurrences of the draw digit (and, if absent, remove all occurrences of its V‑TRAC mate).
Pros: fast path to a clean 3‑value residue.

Remove “as‑is” (one at a time)—i.e., the first occurrence only—then keep reducing step‑by‑step.
Pros: preserves repeats and structure; often exposes pending patterns (e.g., leaving one “5” intact can retain a “59*” scaffold that collapses to “590” one step later).

Both are valid; your system explores both to see which one reveals the resilient pattern. This is not jargon—it’s the heart of the method.

V‑TRAC (mirror) is not optional; it is the hidden gateway

Mirror pairs: 0↔5, 1↔6, 2↔7, 3↔8, 4↔9.

We consider exact permutations and any 3‑digit from the same local V‑TRAC family as hits (with different strength).

Practically: treat a lingering “6118” as informative support for “618”; treat “7544” as signaling 4↔9 pressure (so “754” and “759” both deserve attention).

C. “Golden indicators” (the rules the scoring must encode)

Below are the signals you’ve been teaching; I’m writing them as implementation‑ready, with suggested weights. “+” means add to score, “−” means subtract.

1) Survival / Earliest‑Step

Exact earliest step (lower is better): + w_early_exact * (max_step + 1 - earliest_exact)

V‑TRAC earliest step: + w_early_vtrac * (max_step + 1 - earliest_vtrac)

Final exact present: + w_final_exact

Final v‑trac present: + w_final_vtrac

2) Vertical persistence (down the reduction)

Count how many reduction levels contain the target exact string.
+ w_vert_exact * levels_exact

Same for V‑TRAC family.
+ w_vert_vtrac * levels_vtrac

3) Cross‑box repetition (R2/R4/R6/R8)

Number of boxes where the (exact or v‑trac) pattern appears in columns 7/6/5
+ w_box * hits_in_boxes

Double bonus for same pattern appearing in multiple sets (Set1/2/3)
+ w_set_bonus * set_count

4) Cross‑variant convergence (Midday / Evening / Combined)

Presence in 2 variants: + w_var2

Presence in all 3: + w_var3

If Combined and the owning variant agree: + w_own_vs_combined_agree

5) Stability / Density

Digit density: lingering doubles/triples (e.g., 61188) indicate sticky structure.
+ w_density * (# of extra same‑digit repeats)

Clutter penalty: extra non‑target digits remaining in the box after reduction.
− w_clutter * (# extraneous digits)

6) Permutation & method consensus

Count of methods (A–E) that surface the same candidate: + w_method_agree * count

Own↔Combined delta small: + w_small_delta; delta large: − w_large_delta

Default bias: exact > v‑trac, earlier > later, wider repetition > single appearance, cross‑variant agreement > single variant, dense/stable patterns > wisps, low clutter > noisy remnants.

We can start simple (e.g., all weights = 1 except w_final_exact=3, w_var3=2) and then tune.

D. Hot‑Zones module: what to reuse (and why)

Hot‑Zones needs to “nibble” one or two digits from shorter strings near the tail, not purge everything. You can reuse the exact same primitives:

reduce_all(value, digit_or_vtrac) – removes all occurrences (the purge).

reduce_once(value, digit_or_vtrac) – removes just one occurrence (the nibble).

vtrac_family(abc) – returns the 3‑digit family (for mirror checks).

score_lingering(value) – applies the same golden indicators on the short strings.

Hot‑Zones then becomes: “try one‑digit (or two‑digit) reduce_once moves over the last N strings; score the resulting scaffold with the same rules; show the best ‘windows’.” That keeps logic unified and maintainable.
