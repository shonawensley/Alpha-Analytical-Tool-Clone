1. What does “consensus” mean here?

Short answer: in all the recent V-TRAC work, consensus is being used in the sense you defined originally – a collapse of the right-edge columns to fewer than 3 distinct digits, typically columns 1 or 2 in Set1.

Your original definition is explicit about that: consensus is when column 1 or 2 ends up with <3 total digits in the R2/R4/R6/R8 stack – a “hard convergence” signal, not a voting metaphor.

The enhanced V-TRAC validator and analysis docs talk about “consensus column 1” and “consensus flags” in exactly that sense – it recomputes hot/super-hot counts and consensus flags per section from the HTML tables, then checks they line up with analyzer exports.

So:

Stable / hot-zone docs: consensus = col1/2 collapsed to <3 digits (what you always meant).

V-TRAC validator / analysis: same concept, just applied to V-TRAC signature tables and surfaced as consensus_col1, consensus_col2 in section summaries.

There isn’t a separate “probabilistic consensus” notion floating around; it’s all that column-collapse signal.

4.2. Add lightweight feature bumps in the scorer
Borrow the same pattern we used successfully in Stable:


Recency / hot-into-col1/2 boost
For each index/variant, you already know:


whether Set1 col1/2 is consensus or super-hot,


whether that signature appears there.


Add a term like:


+w_recency_col1 if signature hits Set1 col1 hot/super-hot


+w_recency_col2 * 0.5 if it hits col2 similarly.




Cross-variant echo bonus
Count in how many of {Combined, Midday, Evening} a given signature shows as stable/super-hot. If count ≥ 2, add a small +w_cross_variant * (count-1).


Straight-lane quality
For each top straight lane in top_straights, record:


how often it appears across variants,


whether it terminates in Set1 col1/2 consensus.


Then add a modest +w_straight_lane when a V-TRAC index owns such a lane.


VT-only emphasis
Identify indices whose evidence is strong in VT signatures but weak on overlap/consensus. You don’t need a new flag in JSON right now; the validator already identifies cases where index is stable but overlap=0.
Give them a small “VT-only stability” bump – enough to lift them a few ranks, not so much that every noisy VT family jumps to the top.


These are all additions on top of existing scores; they don’t break any files.
4.3. Don’t obsess over getting every winner into top-3

Getting to 80–90% “top-5 coverage” across your 2–3 test days is more than enough to freeze the module and move on.
