  is_exact_{straight,boxed} + is_vtrac_boxed) would make the analysis log and any GPT reviewer immediately see “this run
  caught 733 straight” without decoding.
  - Column‑2 → Column‑1 funnels: Connecticut’s 494 and Indiana’s 273/167 all spent multiple draws lighting column 2
  with double stars before dropping into column 1, yet Stable’s compound metric gave them zero col1_hits because it
  only counts distinct column‑1 rows. As a result those winners ranked >100 while column‑1 double families dominated. A
  dedicated metric/bonus for “pre-column‑1 funnel” would promote the patterns that clearly surged toward column 1 even
  if the last hop was column 2.
  - Combined coverage regression: Florida’s midday 733 canonical (337) only appeared in the Evening section of the
  scores/compound CSVs, meaning Combined never saw the actual straight even though the HTML showed overwhelming column‑1
  evidence. That’s likely a multi-variant ingest bug; until Combined rows exist for every spotlighted canonical, midday
  hits can’t bubble up, so we need a coverage gate/test that fails when a winner is missing from the Combined ledger.
  - VT-lane weighting in mid columns: Florida’s 271 (family 127) and Ontario’s 771 relied heavily on VT-straight paths
  across columns 3–5. Stable tagged those lanes (score_vtrac_straight=2–3), but compound only adds +1 for VT hits, so
  these winners stayed buried behind high hot2/double families even when they were the actual hit. Stronger weighting
  (or a separate “mid-column VT lane” bonus) would let VT-driven winners surface without requiring them to show column‑1
  persistence.

  These four items came straight out of the per-state write-ups: every time a winner lagged in compound rank we could
  tie it to one of those gaps. Addressing them would make Stable’s scoring line up with the visual evidence we saw in
  the V-TRAC winners and string tables.
