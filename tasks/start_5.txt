Preflight Purpose

- CWD check: Confirms the session runs from repo root so imports and relative paths behave predictably.
- Interpreter check: Ensures you’re using the intended Python, reducing “works here, not there” issues.
- Import origins: Verifies key modules resolve to in-repo files (no site-packages shadowing).
- Data presence: Quickly inventories data/cleaned/*_draws.csv so pages that depend on them won’t start empty.

Why “Connecticut4” and Draws CSV

- Example state: “Connecticut4” is a simple, consistent sentinel that’s present in your cleaned draws. You can pass any state; it’s not hardcoded beyond the example.
- Draws CSV baseline: Aux & Blackapple consume only data/cleaned/*_draws.csv. Validating a known-good draw file is the fastest universal smoke test for the app’s “data at rest” without invoking the full
combined-tables pipeline.
- Not a shortcut for Aux only: The preflight’s primary value is path/import sanity, not just data. Even when you’re working on Stable/DR/V‑TRAC, confirming imports resolve to in-repo modules and that the repo
has data is universally helpful.
- Why not check combined tables here? Keeping preflight fast avoids long scans. Combined tables are validated:
