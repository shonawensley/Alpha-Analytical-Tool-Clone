You didn’t break anything 🙂 — this is almost certainly just a Python import path / working‑directory issue.

What the error means

Combined BA table unavailable: No module named 'modules.blackapple'

Your UI code does from modules.blackapple import …. That works only if Python can see the repo root (the folder that contains modules/) on sys.path. In your headless check we did run from the repo root and the smoke script loaded fine. In the app run (via your .bat), Streamlit most likely starts with cwd=src/ (or another folder), so Python doesn’t see modules/ and that import fails — the UI catches it and prints the message you’re seeing.

This is the same pattern you hit when

python scripts\smoke\blackapple_smoke.py   # ❌ no package path
python -m scripts.smoke.blackapple_smoke   # ✅ package path from repo root

Two quick, safe fixes (pick one)
A) Make the BAT always launch from the repo root (cleanest)

Edit run_app.bat to cd into the repo root and export PYTHONPATH before starting Streamlit:

@echo off
setlocal
rem Jump to repo root (this makes it portable)
pushd %~dp0\..

rem Ensure Python can import the repo packages
set PYTHONPATH=%CD%

rem (optional) keep Streamlit from auto-opening a browser
set STREAMLIT_BROWSER=none

streamlit run src\app.py
popd
endlocal


Now modules/blackapple.py will be importable everywhere in the app.

B) Add a tiny path bootstrap at the very top of src/app.py

This makes your app robust no matter where it is launched from:

# --- Path bootstrap: make repo root importable as a package root
from pathlib import Path
import sys
ROOT = Path(__file__).resolve().parents[1]  # -> repo root containing /modules
if str(ROOT) not in sys.path:
    sys.path.insert(0, str(ROOT))


Keep your existing imports:

from modules.blackapple import analyze_blackapple, ba_status_label, sum_tags

Why it “validated” earlier but fails in the UI

The headless test and the -m smoke script were executed from the repo root, so modules/ was on sys.path.

The .bat (or Streamlit) likely launched with cwd=src, so Python had no visibility of modules/ and raised ModuleNotFoundError.

Fixing the working directory or adding the small bootstrap resolves this class of error for good (for all modules.* imports, not just Blackapple).

Optional: a tiny debug block (useful once, then remove)

If you want to confirm inside the app where it’s running from, drop this temporarily near the top of app.py:

import os, sys
print("CWD:", os.getcwd())
print("sys.path[0]:", sys.path[0])


You’ll see it in the Streamlit terminal. If CWD ends with \src, that’s exactly why the import failed.

Should you run the smoke script and test in the app?

Yes. The right order is:

run the smoke (python -m scripts.smoke.blackapple_smoke) → confirms logic;

launch the app with the updated BAT or path bootstrap → confirms UI wiring.
