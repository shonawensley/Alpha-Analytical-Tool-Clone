Reasoning
When Streamlit runs src/app.py, Python places src on sys.path. Because src appears before the project root, the absolute import from utils.path_handler import ... resolves to src\utils first.
That triggers src\utils\__init__.py, which imports .path_handler, which is the forwarder shown above.
The forwarder tries from utils.path_handler import * expecting “utils” to point to the top-level package, but because “utils” currently points to src\utils, this creates a self-import/cycle. The module ends up partially initialized and does not expose get_cleaned_data_dir, yielding:
ImportError: cannot import name 'get_cleaned_data_dir' from 'utils.path_handler' (…\src\utils\path_handler.py)
Why it worked before, sometimes: if the project root was at the front of sys.path early enough (or a different import order occurred), utils resolved to the canonical package and things ran. Small changes in launch method, reload timing, or extension behavior shift the import order, making it flaky.

Import shadowing: src\utils is taking precedence over the canonical utils due to sys.path order and early imports in src/app.py that use utils before bootstrapping the project root.
